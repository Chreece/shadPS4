# Resource-range package build repair — 2026-10-21

Parent package: `6850b3cc3bb31dc8ed6da53ec6cb77efb35e2367`.

The host build stopped in `CalculateBufferAddress` at line 1780 of the
transformed `resource_patching_pass.cpp`. The conditional operator mixed
`IR::U32` with the `IR::U32U64` returned by `IREmitter::BitwiseAnd`. Both
wrapper types can convert to one another, making that conditional ambiguous.
This is a source-package defect, not a compiler installation problem.

The generated replacement now uses an ordinary `if` and an explicit
`IR::U32` result. The 32-bit mask, address arithmetic, resource-range analysis
and cache versions are unchanged. There are no game-specific changes.

A second package defect was found while checking the failure report:
`CORRECTED_SOURCE_MANIFEST=PASS` was written to the console, but candidate
verification searches for it in `host-tests.log`. The Python verification
block now pipes its output through `tee -a` to that log. `pipefail` remains
active, so an invalid manifest still aborts the build rather than passing.

After staging and CMake configuration, the generated host script compiles the
actual `resource_patching_pass.cpp` and `recompiler.cpp` objects first. This
checks both the corrected emitter expression and the new final-IR analysis
header against the real source/dependency graph before the remaining build.
Failures still use the existing source/executable restoration trap. No
submodule, runtime, save, game-control or Ollama policy was changed.
