Separate null sentinel sits at slot 27,651. No other reject reasons observed. Because image-type check is first, GPU mapping / format validation for those 39 does not follow; nonzero raw image addresses do not establish valid Vulkan memory.

**Generic emulator gap proven:** current `ImageResource::GetSharp` uses compile-time null 2D image for guest-indexed arrays; SPIR-V `EmitImageSampleImplicitLodIndexed` emits one statically typed 2D sampled-image array and 2D coordinate handling. Vulkan 3D and Cube views cannot be stored in that 2D array. Simply deleting the type gate or coercing arbitrary 3D/Cube to 2D would be invalid. Correct future support needs *dimension-typed arrays* plus a GPU-side mapping from original guest index to the appropriate typed slot, preserving nonuniform selection, real samplers, coordinate semantics and null sentinel. **The 39 unbound entries are not yet proven to be executed on this menu.** Historical 2026-10-19 instrumented draw capture for `0x7eaf40ad` had zero executed sample IDs across three selected draws; verify current actual GPU sample IDs and vertex/fragment invocations before assuming the 39 cause missing solid geometry.

Remaining: 81 SHARP warnings, 1,733 huge buffer clamps (also present in earlier more visually complete captures), 0 SRT stalls in menu. **PR #72 closed unmerged after diagnosis**, not mistaken for a rendering fix. Previously missing shader-profile fields and Vulkan image-gather feature getter were restored to the public development branch before native compilation.
