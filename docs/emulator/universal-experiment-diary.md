### Pending: nonblocking GPU fault readback ring — source 877ae834841aaf0ebbed26f8cabff8aa41f1e6b2

- **New source-only candidate, untested.** The fault parser formerly invoked `scheduler.Wait(wait_tick)` and `scheduler.PopPendingOperations()` from `Rasterizer::OnSubmit`, which is called by `Scheduler::SubmitExecution` while holding global `submit_mutex`. GPU wait/reentrant submission can stall all work when the eight-slot fault ring rotates.
- Replacement returns a retry result without a GPU wait whenever the current readback slot is owned by an incomplete GPU submission. `BufferCache::TickFrame` retains `fault_process_pending` when scanning is deferred; the callback frees the slot on completion. A compiler marker logs first/every-256 deferrals and subsequent recovery. This does **not** replay first-touch shader reads that already returned zero.
- Four focused CTest cases added for zero slot, occupied slot, all-eight-occupied ring and completion/retry. Active expected gate is **29** tests (25 retained plus four). The nine zero-recovery uniform-lane tests are removed from active CMake but kept in Git history.
- Isolated cached runner: `scripts/shadps4_gow_srt_fault_ring_20261026.sh` at `cd558bfe6a643a77cec771839f74a1ddb7583d5d`. It verifies pinned source, precompiles both buffer-cache files before linking, enforces shared build locks, preserves stable candidates, and runs same 118+2s native test and diary writer.
