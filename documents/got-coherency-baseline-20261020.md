# Precise readback baseline

The 113611 capture ran candidate `4f0749f5d018f45df77723d9db6362731cbd8cc6` with `GPU readbacksMode: 0` (Disabled). Its host archive reports a successful full build. The runtime shows repeated CPU uploads of pages containing observed zero-count indirect commands, including page `0x1548c1c000`. These overlaps do not establish which bytes the CPU intended to change or prove that a nonzero GPU count was overwritten.

`MemoryTracker::InvalidateRegion` skips the GPU flush when readbacks are disabled. `BufferCache::SynchronizeMemory` then uploads entire CPU-dirty pages. A CPU write next to a GPU-written word can therefore replace that word with stale host data. Simply excluding GPU-dirty ranges from uploads would be incorrect: it could also discard intentional CPU writes to those ranges.

An external reproduction compiled against the actual memory-tracker and region-manager headers with stub settings and page watchers. It simulated a GPU count of 37 and a CPU write to a neighboring word in the same 4096-byte page. Disabled mode produced count 0 with no flush callback; Relaxed and Precise produced 37 with one flush callback. Only Precise requested read protection. The simulated flush copied the GPU word back before the CPU write. This establishes the tracker behavior, not the game's producer values, OS fault handling, or Vulkan execution.

The runtime script now selects existing Precise mode (`GPU.readbacks_mode = 2`) in the isolated copied profile and any existing title override. It verifies the effective mode in the startup log and rejects a capture without that confirmation. This is a diagnostic accuracy configuration, not a new emulator implementation fix or title-specific rendering workaround. The original profile, executable, shader behavior and guest render state remain unchanged. Candidate and shader-collector pins remain at the successful build. Continue is still pressed at 150 seconds during the 300-second run.

Validation: shell syntax, configuration cases with absent/empty/conflicting title overrides, preservation of unrelated settings, and effective-mode log matching passed. No emulator source changed and no new emulator build is claimed. Native gameplay has not been run here. Compare menu/world images, indirect argument values and pipeline invocations with the disabled baseline before attributing any improvement to coherency. If the visual defects persist, precise mode has only removed a confounding factor; it has not resolved them.

Other evidence: indexed feedback reported 11,680,908 samples with no out-of-range indices or nonfinite sampled values, limited to recorded bindings. Grass NaN positions occur on an explicit guest rejection path. Neither finding justifies modifying the guest's output to force visibility. All remaining menu and world defects are still unverified.
